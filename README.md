# steam_api.dll — полная реконструкция (CS 1.6, build 10210, 2024)

Реконструкция `steam_api.dll` из актуального билда Counter-Strike 1.6 (25th Anniversary Update, build 10210) методом чистой комнаты. **Весь код в этом репозитории — оригинальный, написан с нуля** на основе анализа публичных заголовков SteamWorks SDK и наблюдаемого поведения оригинальной библиотеки. Никакой код Valve не используется и не копируется.

## Как это работает

Библиотека экспортирует **1070 функций** (имена и ординалы соответствуют оригиналу) и работает в одном из двух режимов, выбираемых автоматически при загрузке:

### Режим 1: Прокси (Steam установлен)

Если рядом с DLL найдена переименованная Valve-библиотека `steam_api_orig.dll` (или Steam в стандартной директории), наша DLL загружает её и прозрачно перенаправляет ей **только жизненный цикл Steam**:

| Функция | Куда идёт |
|---|---|
| `SteamAPI_Init` / `Shutdown` / `RunCallbacks` | оригинал |
| `SteamClient` | оригинал |
| `GetHSteamPipe` / `GetHSteamUser` | оригинал |
| `SteamAPI_RegisterCallback` / `RegisterCallResult` | оригинал |
| `SteamInternal_ContextInit` / `FindOrCreate*Interface` | оригинал |
| `SteamInternal_GameServer_Init` | оригинал (naked-транзит) |

Всё остальное — **более 1050 функций интерфейсов** — выполняется нашим кодом на наших vtable-совместимых классах.

**Результат:** игра полностью работает через настоящий Steam-клиент, видна друзьям как Steam-сессия, VAC активен — при этом вся интерфейсная логика обслуживается нашей реконструкцией.

### Режим 2: Оффлайн (Steam не найден)

Если оригинал не обнаружен, DLL работает **полностью автономно** на собственных реализациях:

- фиктивный SteamID `0x110000100001`, ник «Player», язык «english»
- «подписка» на приложение 10 (Counter-Strike) активна
- встроенный P2P через UDP (loopback/LAN) с очередью пакетов и фрагментацией
- локальные лобби в памяти процесса с фильтрами
- локальный Workshop на файловой системе (`workshop/` рядом с DLL)
- VGUI2-заглушки для совместимости

## Vtable-совместимость

Реализации интерфейсов (`src/interfaces/`) построены по **официальным заголовкам SteamWorks SDK** (`isteamuser.h`, `isteamfriends.h`, `isteamutils.h` и др. из source-sdk-2013). Порядок виртуальных методов каждого класса соответствует раскладке Valve:

| Интерфейс | Слотов | Статус |
|---|---|---|
| `ISteamUser023` | 33 | реализован |
| `ISteamFriends017` | 80 | реализован |
| `ISteamUtils010` | 36 | реализован |
| `STEAMAPPS_INTERFACE_VERSION008` | 30 | реализован |
| `ISteamMatchmaking009` | 38 (используемых) | реализован |
| `ISteamUserStats012` | 45 | реализован |
| `ISteamNetworking006` | 22 | реализован |
| `ISteamClient021` | 42 | реализован |
| `ISteamMusic` | 9 | реализован |

Виртуальные деструкторы не объявлены (как у Valve-интерфейсов), поэтому vtable наших объектов начинается с метода 0 — бинарная совместимость с движком GoldSrc.

## Структура проекта

```
CMakeLists.txt            — сборка (CMake ≥ 3.15, MSVC Win32)
build.bat                 — сборка одной командой
sign.bat                  — опциональная self-signed Authenticode-подпись
include/steam/            — публичные заголовки (steam_api_goldsrc.h, steam_api.h)
src/core/                 — DllMain, 1070 экспортов, DEF-файл, прокси, диагностика
src/interfaces/           — реализации ISteam*-классов (SDK-совместимые vtable)
src/net/                  — UDP-сокеты, P2P-менеджер (loopback/LAN)
src/lobby/                — локальные лобби с фильтрами
src/workshop/             — локальное хранилище Workshop
src/vgui/                 — VGUI2-заглушки
tests/                    — интеграционные тесты (загрузка DLL, проверка экспортов)
```

## Сборка

Требуется **Visual Studio 2022 Build Tools** (MSVC x86) и **CMake**:

```bat
build.bat
```

Результат: `build\Release\steam_api.dll` (x86, ~1070 экспортов).

## Запуск

1. Положи `steam_api.dll` в папку игры (рядом с `hl.exe`)
2. Для прокси-режима: оригинальная Valve DLL должна лежать рядом под именем `steam_api_orig.dll`
3. Для оффлайн-режима: просто убери `steam_api_orig.dll` — DLL переключится сама

Пользовательские данные создаются в `steam_user_data/`, Workshop — в `workshop/`.

## Диагностика

DLL пишет лог `steam_api_diag.log` рядом с собой: загрузка, режим, вызовы инициализации, контекст, краши (через Vectored Exception Handler с резолвом модуля). Это инструмент разработки — можно отключить, убрав `diag_log.cpp` из сборки.

## Модификация

Весь код открыт для изменения:

- `src/interfaces/*.h/.cpp` — поведение любого интерфейса (ответы методов, состояния)
- `src/net/`, `src/lobby/`, `src/workshop/` — сетевая и локальная логика
- `src/core/exports.cpp` — таблица экспортов, маршрутизация вызовов
- `src/core/proxy.cpp` — поиск и загрузка оригинальной DLL для прокси-режима

Сборка своей версии: `build.bat` → `build\Release\steam_api.dll` → положить в игру.
